# Sitevik Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a minimal Rust static-site server with directory indexes, an optional extension-aware SPA fallback, and secure Actix path handling.

**Architecture:** A small configuration module validates environment-derived settings. A server module constructs a root-mounted `actix_files::Files` service and owns the narrow fallback policy, while the binary entry point only loads configuration, binds Actix, and runs.

**Tech Stack:** Stable Rust 2024 edition, `actix-web` 4, `actix-files` 0.6, and `tempfile` 3 for tests.

## Global Constraints

- `SITEVIK_ROOT` selects the content directory and defaults to `./dist`.
- `BIND_ADDR` selects the socket address and defaults to `0.0.0.0:8080`.
- `SITEVIK_SPA` is unset, `true`, or `false`; every other value is a startup error.
- Support only `GET` and `HEAD`; other methods return 405.
- Serve hidden files, disable directory listings, and do not redirect directory URLs.
- Reject literal, encoded, and malformed traversal paths with 404.
- Use normal operating-system symlink behavior; add no symlink policy.
- Missing final path segments containing `.` never receive the SPA fallback.
- Do not add TLS, CLI parsing, proxy handling, file watching, compression configuration, custom caching, custom errors, or authentication.
- Release builds use `opt-level = 3`, fat LTO, one codegen unit, stripped symbols, and abort-on-panic behavior.

---

## File Map

- `Cargo.toml`: package metadata, runtime/test dependencies, and optimized release profile.
- `Cargo.lock`: reproducible dependency resolution generated by Cargo.
- `src/lib.rs`: public module boundary used by the binary and integration tests.
- `src/config.rs`: environment value parsing and content-root validation.
- `src/server.rs`: Actix file service, fallback classification, and safe error mapping.
- `src/main.rs`: process startup and HTTP server lifecycle.
- `tests/http.rs`: in-process request tests for the complete HTTP contract.

- [ ] **Step 3: Implement the base Actix file service**

In `src/server.rs`, construct:

```rust
Files::new("/", root.clone())
    .index_file("index.html")
    .use_hidden_files()
    .default_handler(fn_service(move |req| {
        fallback(req, root.clone(), spa)
    }))
```

Do not call `show_files_listing` or `redirect_to_slash_directory`. Rely on
`Files` default method handling for GET, HEAD, and 405 responses.

Add a fallback helper that reparses
`req.match_info().unprocessed()` with
`actix_files::PathBufWrap::parse_path(..., true)`. Although Actix validates the
path before calling the default handler, this second parse ensures the helper
never joins an unvalidated request path.

- [ ] **Step 4: Complete the fallback error policy**

The helper must inspect `root.join(validated_path)` before deciding:

```rust
match std::fs::metadata(&candidate) {
    Err(error) if error.kind() == ErrorKind::NotFound => {
        // Apply missing-route SPA classification.
    }
    Err(_) => return internal_server_error(req),
    Ok(metadata) if metadata.is_dir() => {
        // An existing directory reached fallback because its index failed.
        // Missing index => 404; other index metadata errors => 500.
    }
    Ok(_) => return internal_server_error(req),
}
```

For a genuinely missing candidate, take the final validated path component.
If `spa` is false or that component contains `.`, return an empty 404. Otherwise
open `root/index.html` with `NamedFile::open_async` and convert it with
`into_response`. Map a missing root index to 404 and any other open error to
500. Use empty 404 and 500 bodies so no local path is disclosed.

- [ ] **Step 1: Write the entry point**

Implement `main` with this control flow:

```rust
#[actix_web::main]
async fn main() -> std::io::Result<()> {
    let config = Config::from_env()
        .map_err(|error| std::io::Error::new(std::io::ErrorKind::InvalidInput, error))?;
    let root = config.root;
    let spa = config.spa;

    HttpServer::new(move || {
        App::new().service(static_files(root.clone(), spa))
    })
    .bind(config.bind_addr)?
    .run()
    .await
}
```

Keep startup free of CLI parsing, TLS configuration, logging dependencies, and
reverse-proxy middleware.
